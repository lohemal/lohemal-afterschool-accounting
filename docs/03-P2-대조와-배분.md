## 2. 프로그램별 징수액 배분 (`allocation`, 스키마 v3)

- 징수명단(기안용)처럼 프로그램 열이 없는 양식의 징수 거래는 프로그램 NULL(미배분)이다. `allocation` 행이 그 거래의 금액이 어느
  프로그램에 귀속되는지 표시한다. **새 징수 거래가 아니며 원장 금액은 그대로다.**
- 제약: 한 거래의 배분 합(절댓값)은 거래 금액을 넘지 못하고 부호가 같아야 한다(트리거 `trg_allocation_cap`). 배분은 고치거나 지울 수 없고
  취소(`status='voided'`)만 된다. 거래가 취소되면(파일 취소·교체·복원) 그 배분도 함께 접히고, 살아 있는 거래의 살아 있는 배분만 집계에 든다.
- 학생 연결은 **학년·반·번호·이름이 모두 같은 `student_id`** 로만 한다. 이름만 같은 후보(동명이인·반 변경 가능성)는 사용자 확인용으로 보여 주기만 한다.
- 자동 배분 규칙(`auto_allocate`):
  1. 같은 학생이 참고 명단에서 **한 프로그램**뿐 → 거래 전액 (`auto_single`). 참고 금액이 징수 금액과 달라도 귀속은 분명하므로 배분하되 사유에 남긴다.
  2. 여러 프로그램 → 그 학생·항목의 징수 거래가 **하나**이고 명단의 프로그램별 금액 합이 **정확히** 같을 때만 명단 금액대로 (`auto_split`).
  3. 그 밖(학생 식별 불가·명단에 없음·동명이인·금액 불일치·재원 여러 개·이미 일부 배분됨)은 자동 배분하지 않는다.
- 수동 배분은 프로그램별 금액을 직접 넣는다. 합이 잔액을 넘으면 저장되지 않고 기존 자료는 그대로다. 남는 금액은 미배분으로 둔다.
- 확정된 달에서는 배분을 넣거나 취소할 수 없다(재개 후 가능).

## 3. 대조 엔진 (`repo::recon`)

- 단위 = 프로그램 또는 프로그램 그룹. 항목 묶음 = 강사료 / 교재·재료비(교재비+재료비+합산 항목) / 수용비 / 기타.
- 재원은 통합 재원(`coalesce(merged_into_id, id)`)으로 묶어 **한 번만** 더한다. '초3 지원금' 으로 들어온 징수와 '방과후이용권' 으로 들어온 지급은 같은 재원이다.
- 재원별로 양쪽 자료가 **다 있을 때만** 비교한다. 한쪽에만 있는 재원(강사료의 맞춤형지원 등)은 '대조 자료 없음'으로 표시하고 차액에서 뺀다.
  행의 차액은 비교 가능한 재원의 합이고, 제외된 재원 이름을 상태 라벨에 붙인다(예: `정상 (맞춤형지원 제외)`).
- 그룹: 그룹 기준액 = 구성 프로그램 기준액 합. 그룹에 지급이 있으면 구성 프로그램의 그 항목은 `그룹으로 검증`(개별 지급액 미확정)이 되고,
  대조 가능 금액에는 그룹만 한 번 든다.

| 상태 | 조건 |
|---|---|
| 검증 불가 | 수용비·기타 |
| 그룹으로 검증 | 지급이 그룹으로 묶여 있음 |
| 배분 미확정 | 이 달에 같은 항목의 미배분 징수액이 남아 있음 (어느 프로그램 것인지 모르므로 모든 프로그램이 미확정) |
| 매핑 미확정 | 재원이 미확정인 거래가 섞여 있음 |
| 자료 부족 | 징수 쪽이나 지출 쪽 자료가 없음. **0원으로 보지 않는다** |
| 불일치 | 비교 가능한 재원에 차액 있음 (재원별 차액을 단서로 표시) |
| 정상 | 비교 가능한 재원이 모두 0원 |

## 4. 확인 메모 (`recon_note`)

덧붙이기만 하는 표. 마지막 줄이 현재 상태(확인 필요·확인 중·사유 확인)다. 저장할 때 그 단위의 검증 지문
(기준액·지급액 구성·거래 id·배분 id 의 해시)을 함께 둔다. 지문이 지금과 다르면 화면에 **재확인 필요**로 뜨고 이전 메모는 그대로 남는다.
'사유 확인'은 시스템 판정을 바꾸지 않는다 — 불일치는 불일치로 남는다.

→ P1 파서가 잘못 읽은 것이 아니라 **제공 전에 개인정보가 제거된 파일**이다. 학생 정보를 임의로 만들지 않았고, 실제 파일로는 학생 단위 배분을
할 수 없다(아래 시나리오 1). 이름이 있는 원본으로 돌리면 같은 코드가 학년·반·번호·이름으로 연결한다(가명 시험 통과).

- 사용자가 실제로 해야 할 매핑: `한자`→`한자급수` 별칭, `우쿠렐레`→`우쿨렐레` 별칭, `키즈쿠킹` = 목요+화요 그룹, `토탈공예미니어처` = 1+2 그룹,
  `전래놀이` = 요일별 5개 그룹, 지원유형 `방과후 이용권 + 자유수강권` 의 재원 결정. 이것들은 프로그램이 추측하지 않는다.
- 원본 추적: 불일치 행(로봇과학 교재·재료비)의 지급 거래 6건이 모두 보관 파일·시트 `2026.9.`·행 번호(8행 등)로 이어진다.

## 7. 남은 제한 · P3 권장

- 매핑을 바꿔도 이미 반영된 거래의 프로그램은 바뀌지 않는다(원장 불변). 지급 파일을 교체(재반영)하면 새 매핑이 적용된다.
  매핑 변경 → 영향받는 파일 목록 → 일괄 재반영 안내가 있으면 편하다.
- 이름이 비어 있는 실제 파일은 학생 단위 배분이 불가능하다. 이름이 있는 원본으로 다시 받아야 시나리오 1 이 실제로 돈다.
- 재원 간 이동(과목경정)·자유수강권 소급 환불 등록 화면(P3·P4), DB 백업·복원 화면은 아직 없다.

# P2.1 보완 — 재원 분류 정비 · 차액 계산 근거 (2026-10-13)

## 재원 분류 (이름이 아니라 id · parent_id 로)

| 재원 | 코드 | 독립 조회 | 수익자 통합 합계 | 근거 |
|---|---|---|---|---|
| 일반 수익자 | `beneficiary` | ○ | ○ (뿌리) | `parent_id` 없음 |
| 초3 초과금 | `g3_excess` | ○ | ○ (하위) | `parent_id = beneficiary` |
| 방과후이용권 (= 초3 지원금 = 3학년 지원금) | `after_voucher` (`g3_support.merged_into_id`) | ○ | × | 독립 |
| 자유수강권 | `free_voucher` | ○ | × | 독립 |
| 맞춤형지원 | `custom_support` | ○ | × | 독립 — 수익자가 아니다 |
| 기타 | `other` | ○ | × | 독립 |

`repo::recon::FundIndex` 가 재원 표를 읽어 통합(`effective`)·뿌리(`root`)를 id 로 푼다. 이름을 바꿔도(예: '수익자 맞춤') 분류는 그대로다(시험 `fund_index_uses_ids_not_names`).
마이그레이션 004 는 시드 이름만 '일반 수익자'·'초3 초과금' 으로 바꾸며 표 구조는 바꾸지 않는다(사용자가 이미 바꾼 이름은 건드리지 않는다).

세부 보기(`funds`)는 재원마다 한 줄, 수익자 통합 보기(`funds_merged`)는 뿌리가 같은 줄을 합친다('일반 수익자(초3 초과금 포함)').
두 보기의 합계는 항상 같고(시험 `check_identities`), 초3 초과금은 통합 보기에서 한 번만 더해진다.

## 차액의 두 가지 뜻

| 값 | 계산 | 쓰임 |
|---|---|---|
| 전체 단순 차액 `simple_diff` | 전체 징수 기준액 − 전체 지급액 | 참고. 비교 범위가 다르면 오류가 아니다 |
| 재원별 대조 차액 `diff` | 비교 가능 징수액 − 비교 가능 지급액 (양쪽 자료가 다 있는 재원만) | **판정 기준** |

항등식: 전체 징수 기준액 = 비교 가능 + 비교 제외(지급 없는 재원) + 매핑 미확정, 전체 지급액 = 비교 가능 + 비교 제외(징수 없는 재원) + 매핑 미확정.
`debug_assert` 와 시험이 모든 행에서 확인한다. 월 합계도 전체 = 비교 가능 + 비교 제외(+ 미배분) 이 성립하며, 그룹으로 검증되는 구성 프로그램 칸은 월 합계에서 뺀다(중복 방지).

비교 제외 재원은 금액과 사유(`excluded`)를 함께 보여 준다 — "재원의 성격 때문이 아니라 비교할 근거 자료가 없기 때문". 맞춤형지원에 대응 징수 자료가 생기면 그 재원도 대조된다(시험 `custom_support_only_payment_and_missing_sides`).

총액이 같아도 재원별로 어긋나면 `불일치` 이며 라벨은 `총액 일치 · 재원 불일치`(`total_match_fund_mismatch`). P3 과목경정의 확인 대상이다.
