# P1 — 엑셀 업로드 · 파일 판(version) · 되돌리기

작성 2026-10-13. 설계 기준은 [01-P0-설계.md](01-P0-설계.md), 이 문서는 P1 에서 **결정한 것과 그 까닭**을 적는다.

## 1. 원장 불변성과 되돌리기가 어떻게 공존하는가

P0 의 원장(`ledger_entry`)은 UPDATE·DELETE 가 트리거로 막혀 있다. P1 의 모든 되돌리기는 이 위에서
**취소(void) + 새 거래 생성**만으로 동작한다.

| 작업 | 원장에서 일어나는 일 | 파일 상태 |
|---|---|---|
| 반영(apply) | 정규화 행(`upload_row`, included=1)마다 거래 1건 INSERT | registered → **applied** |
| 교체(replace) | 옛 판의 살아 있는 거래를 전부 void(사유 '…으로 교체') → 새 판 거래 INSERT | 옛 판 **replaced**, 새 판 applied |
| 취소(cancel) | 그 파일의 살아 있는 거래만 void. 다른 파일 거래는 손대지 않는다 | **cancelled** |
| 복원(restore) | 현재 적용 중인 판의 거래를 void → 복원 대상 판의 **저장된 정규화 행**에서 거래를 새로 INSERT | 현재 판 replaced, 대상 판 applied |

- 같은 자료의 판들은 **계보(`lineage_id`)** 로 묶이고, 계보 안에서 '적용 중'(applied)은 항상 하나다. v1 → v2 → v1 → v2 를 되풀이해도
  살아 있는 거래는 그 판의 것뿐이고, 취소된 거래는 전부 남는다(시나리오 D 시험).
- 반영 직후 **검산**한다: 원장에 실제로 들어간 징수·지출 합계가 미리보기 합계와 1원이라도 다르면 트랜잭션을 되돌린다.
- 반영·취소·복원은 각각 `Db::write` 한 트랜잭션이다. 도중 실패 시 DB 는 이전 상태 그대로다(시나리오 E 시험).
- 원본 파일은 `자료폴더/uploads/<sha256>.<확장자>` 에 보관한다(내용 주소 → 같은 내용은 한 번만, 복사는 멱등). 파일 복사는
  트랜잭션 **앞**에서 하며, 반영이 실패해 DB 에 없는 파일이 남으면 앱 시작 때 `cleanup_orphans` 가 치운다.

## 2. 중복 집계를 막는 규칙

한 경제적 거래를 여러 파일이 표현할 수 있으므로 업로드마다 **자료 유형**을 고른다.

| 자료 유형 | 원장 | 쓰임 |
|---|---|---|
| `initial_collect` 최초 징수 | ○ | 징수명단(기안용) · 통합 매니저 명단(최초 징수 시점) · 1학기 정산 명단(징수·환불·추가징수 세 유형으로) |
| `extra_refund` 추가징수·환불 | ○ | 환불 및 추가징수 명단 |
| `instructor_pay` 강사료 | ○ | 강사료 지급 내역 |
| `vendor_pay` 교재·재료비 | ○ | 교재·재료비 지급업체 |
| `roster_link` 프로그램 연결·검증 | × | 프로그램별 수강생명단 — 정규화 행만 저장 |
| `snapshot` 참고 스냅샷 | × | 최신 수강생명단 등 |

- 같은 귀속월에 `initial_collect` · `instructor_pay` · `vendor_pay` 적용본은 **하나만** 허용한다. 둘째 파일은 '교체'로만 올릴 수 있다
  (`extra_refund` 는 한 달에 여러 파일이 있을 수 있어 제한하지 않는다).
- 같은 내용(sha256)의 파일은 살아 있는 동안 다시 올릴 수 없다(이름이 달라도).
- 징수명단(기안용)의 **전체 시트는 합산하지 않고** 재원별 시트(수익자·방과후이용권·자유수강권)만 반영하며, 전체 시트 합계와 대조해
  일치 여부를 파일 검사 결과로 보여 준다. 방과후이용권 시트의 '이용권' 열은 방과후이용권, '초과' 열은 초3 수익자 부담금이다.

## 3. 미배분 · 미확정

양식마다 없는 정보가 있어 `ledger_entry.program_id` 와 `fund_type_id` 를 NULL 허용으로 바꿨다(마이그레이션 002, 표 재생성).

- 징수명단(기안용)에는 프로그램 열이 없다 → 거래는 **미배분**(program NULL). 프로그램 연결은 P2 에서 `roster_link` 자료로 한다.
- 1학기 환불·추가징수 명단과 정산 명단에는 재원 열이 없다 → **미확정**(fund NULL).
- 통합 매니저 명단의 지원유형 `방과후 이용권 + 자유수강권` 은 두 재원이 섞여 있어 추측하지 않고 미확정으로 둔다(사용자가 별칭을 걸 수 있다).
- 프로그램을 **알 수 없는 표기는 반영을 막고** 매핑을 요구한다(원장에 프로그램 없는 거래가 생기면 안 되므로). 재원을 모르는 것은
  경고만 하고 미확정으로 반영한다(금액 합계는 맞아야 하므로).

## 4. 재원 통합

`초3 지원금`(`g3_support`) 은 방과후이용권(`after_voucher`) 과 같은 재원이다. 행을 지우지 않고 `merged_into_id` 로 접었다.
기존 id·거래가 그대로 남고, 모든 집계는 `coalesce(merged_into_id, id)` 로 통합 대상에 더한다. 별칭표(`fund_type_alias`) 시드:

| 재원 | 별칭(공백 제거 비교) |
|---|---|
| 방과후이용권 | 방과후이용권 · 초3지원금 · 3학년지원금 · 이용권 |
| 초3 수익자 부담금(초과금) | 초3수익자부담금(초과금) · 초3수익자 · 3학년수익자 · 초과금 |
| 수익자 | 수익자 · 수익자징수 · 수익자징수금액 · 일반 · 일반수익자 |
| 자유수강권 | 자유수강권 · 자유 |
| 맞춤형지원 | 맞춤형지원 · 맞춤형지원(시간당40,000원) |

지원 대상 학년은 재원의 속성으로 두지 않았다(학년도별 정책으로 확장).

## 5. 프로그램 표기 매핑

- `program_alias` 는 프로그램 **또는** 그룹(`program_group`)을 가리킨다. 그룹은 '우쿨렐레&통기타' 처럼 한 지출 행에 합산된 묶음이며,
  거래는 `program_group_id` 로 남고 **개별 프로그램에 배분하지 않는다**.
- 자동 매칭은 대표 이름·별칭·그룹 이름의 **정확한 일치**뿐이다. 끝의 반 글자(A·B·C)를 뗀 이름이 있으면 **제안**만 한다.
- 교재·재료비 파일의 부서명 공란 행: 병합 셀의 아래 칸이면 이어받고(실제 9월 파일 3행 모두 병합), 병합이 없으면 '확인 필요'로 막고
  행 단위 지정(`overrides`)을 받는다. 원본 엑셀은 바꾸지 않는다.

## 6. 수식 셀

calamine 은 저장된 계산값을 읽는다. 계산값이 없는 수식 셀(엑셀이 계산하지 않고 저장했거나 다른 도구가 만든 파일)은 **0 으로 보지 않고
오류**로 올린다. 금액 칸이든 합계 칸이든 마찬가지다. 가명 시험 파일 `instructor_pay_formula.xlsx` 가 이 경우다.

## 8. 남은 제한 · P2 로 넘기는 것

- 미배분 거래(징수명단)를 `roster_link` 자료로 프로그램에 배분하는 로직 — P2.
- 재원 간 이동(과목경정)·자유수강권 소급 환불 등록 화면 — P3·P4.
- 월별 징수 vs 지출 대조·차액 — P2.
- 매핑을 바꿔도 이미 반영된 거래는 바뀌지 않는다(원장 불변). 다시 반영하려면 파일을 교체하거나 취소 후 재적용한다.
- DB 백업·복원 화면은 아직 없다(마이그레이션 전 자동 백업만 있다).
