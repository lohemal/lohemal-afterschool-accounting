# P7-1.1 — 세부반 → 통합 프로그램 매핑 (프로그램 그룹 매핑 및 회계 검증 개선)

작성 2026-10-13. 기준 문서 [01-P0-설계.md](01-P0-설계.md), 대조 규칙 [03-P2-대조와-배분.md](03-P2-대조와-배분.md). 앱 버전 0.1.0 유지, **스키마 v10**.

## 1. 문제

학생 징수자료는 세부반(`로봇과학A`·`로봇과학B`) 단위이고, 강사료·교재재료비 지출자료는 프로그램(`로봇과학`) 단위다.
이름을 그대로 비교하면 세부반은 징수만, 통합명은 지급만 있어 전부 '자료 부족'이 되고 큰 양수·음수 잔액이 보였다.
종전 권장 흐름(세부반 표기를 통합명의 **별칭**으로 합치기)은 숫자는 맞지만 원장에서 세부반 구분이 사라진다.

## 2. 구조 — 기존 구조 분석 결과와 설계 결정

| 기존 | 역할 | 이번 단계 |
|---|---|---|
| `program` | 프로그램 행. 세부반도 통합명도 모두 여기 | 그대로 — 세부반·통합 프로그램 모두 program 행 |
| `program_alias` | 파일 표기 → 프로그램/그룹 (업로드 때 해석) | 그대로. '우쿠렐레'→'우쿨렐레' 같은 오타용 |
| `program_group` | 두 프로그램이 한 지출 행에 합산된 묶음('우쿨렐레&통기타') | 그대로. 구성원이 통합 프로그램이면 합산된 칸을 받는다 |
| `ledger_entry.program_id` | 거래의 프로그램 (불변) | 그대로 — 세부반 거래는 세부반, 지급은 통합명 |
| **신규 `program_link`** | 세부반 → 통합 프로그램 (세부반당 하나, 깊이 1) | 대조 엔진이 세부반 칸을 통합 칸에 한 번씩 합산 |
| **신규 `program_link_log`** | 연결 변경 이력 (지우지 못함) | 변경 일시·대상·이전·이후·유형·근거·사용자 확인 |

통합 프로그램을 별도 실체로 두지 않은 까닭: 지급 거래는 이미 `program_id`(통합명)로 원장에 있고 원장은 불변이라 옮길 수 없다.
program 행끼리 잇는 연결표면 원장 거래·별칭·그룹·업로드 해석을 하나도 바꾸지 않는다. 연결은 저장된 검증 결과가 없으므로
다음 조회부터 바로 반영된다(대조는 매번 계산).

학기·기수: 연결은 학년도 단위다. 같은 학년도 안에서 학기별로 구성이 바뀌면 월 확정과 변경 이력으로 추적하고, 거래는 귀속월로 구분된다.

## 3. 규칙

- 세부반 하나는 통합 프로그램 하나에만(UNIQUE). 통합 프로그램은 다시 세부반이 될 수 없다(깊이 1). 그룹 구성원은 세부반이 될 수 없고 세부반은 그룹에 들어갈 수 없다(지급 중복 방지). 통합 프로그램은 그룹 구성원이 될 수 있다.
- **자동 추천**(`domain::program_link::split_class_suffix` + `repo::program_link::suggestions`): 끝의 반 구분(영문 대문자 하나 또는 숫자 하나, 뒤에 '반' 허용, 앞의 공백·-·_ 무시)을 뗀 바탕 이름이 두 글자 이상이고 끝 글자가 영문·숫자가 아니며(`ABC`→`AB` 금지), 그 이름의 프로그램이 **지급 자료를 갖거나 이미 통합 프로그램이거나 그룹 구성원**일 때만 추천. 바탕 이름이 그룹이거나 이미 세부반이면 추천하지 않음. 지급 자료가 아직 없으면 '후보(조건 미충족)'로만 표시(직접 연결은 가능).
- 추천은 저장하지 않고 매번 계산한다. 표에 있는 연결은 전부 사용자가 확정한 것. 확정 전에는 회계 검증에 적용하지 않는다.
- 확정·변경·해제는 미리보기(`preview`) → 적용(`apply`, 재검증 후 하나라도 막히면 전부 취소). 미리보기는 대상·이전/이후·징수·지급·경고·영향받는 달을 보여 준다.
- **월 확정 보호**: 세부반에 거래(직접 귀속·배분)가 있는 달이 확정 상태면 연결을 바꿀 수 없다. 월별 정산에서 재개한 뒤 바꾸고 재확정한다. 거래가 없는 세부반은 영향 달이 없어 바로 연결된다.
- 업로드 미리보기의 제안: 바탕 프로그램에 지급 자료가 있으면 "세부반으로 등록 + 연결"(`new_child`)을 기본 제안, 없으면 종전처럼 표기 잇기(별칭)를 제안. 둘 다 사용자가 고른다.
- 확정 매핑 재사용: 세부반은 프로그램이므로 같은 표기는 이름으로 바로 해석된다. 세부반에 지급이 직접 붙으면(충돌) 자동으로 바꾸지 않고 통합 행의 단서·무결성 검사 '세부반 직접 지급'으로 알린다.

## 4. 대조 계산 (`repo::recon`)

1. 거래를 프로그램×항목 칸에 모은다(종전과 같음: 최초징수·추가징수·환불 부호 그대로, 재원경정 쌍, 배분, 재원별 분리).
2. 확정된 연결이 있는 세부반 칸을 통합 프로그램 칸에 **한 번씩** 합산(징수·지급 모두)하고 목록에서 뺀다. 통합 프로그램 자신의 거래는 '직접 귀속' 줄로 남긴다.
3. 그 다음 그룹이 구성원(합산된 통합 칸 포함)을 흡수한다.
4. 판정·재원별 대조·항등식(전체 = 비교 가능 + 비교 제외 + 미확정)은 종전 규칙 그대로. 강사료와 교재·재료비는 항목별로 따로.

새 상태 `link_pending` **매핑 확인 필요**: 추천이 확정되지 않은 세부반 행과 그 추천 통합 프로그램 행. 원본 징수액·지급액은 그대로 보이고 차액은 판정하지 않는다('—'). 우선순위 맨 앞.
상태 라벨 정비(지시서 9장): 자료 부족 → **자료 확인 필요**, 불일치 → **차액 확인 필요**, (재원) 매핑 미확정 → **재원 매핑 미확정**. 코드(`missing`·`mismatch`·`unmapped`)와 판정 규칙은 그대로다.

통합 행(`is_parent`)은 `children`(세부반 줄: 최초징수·추가징수·환불·기준액·거래 수, 직접 지급이 있으면 표시)을 가진다. 지급은 통합 행에만 있고 세부반 줄에 다시 표시하지 않는다. 월 합계·대시보드는 세부반을 다시 더하지 않는다(세부반 행은 목록에 없다).
확인 메모 지문에 세부반 구성이 들어가므로 연결을 바꾸면 '재확인 필요'가 된다. 상세 보기의 징수 내역·취소된 거래·관련 학생/업체는 세부반 거래까지 포함한다.

## 5. 화면

- **프로그램 매핑**(자료 → 프로그램 매핑, `/programs`): 세부반 매핑 표(프로그램·역할·징수·지급·추천 통합 프로그램·매핑 상태·수동 선택·확정/변경/해제), 보기 필터(전체·추천 미확정만·매핑되지 않은 것만·확정만), 추천 전체 확정(미리보기 모달: 건수·대상·영향 달·확정된 달 차단·경고), 통합 프로그램 직접 생성, 통합 프로그램별 연결 세부반, 변경 이력.
- **월별 정산 / 차액 분석**: 통합 행은 ▸ 로 펼쳐 세부반 징수를 본다. 상단에 '매핑 확인 필요' 통계와 **미매핑 N건** 영역(원본 프로그램명·항목·금액·추천·매핑 관리 단추). 상세 창에 '세부반 합산 내역' 표.
- 업로드 미리보기 매퍼: "세부반 '로봇과학A' 로 등록하고 통합 프로그램 '로봇과학' 에 연결" 제안, 세부반 등록 대상 선택 목록.
- 설정 → 프로그램 표에 '통합 · 세부반' 열. Excel 월별 검증에 세부반 줄(`└ 로봇과학A`, 상태 '세부반 (통합 행에 합산됨)').
- 무결성 검사 추가: 연결 구조 오류(깊이·그룹·학년도, error), 세부반 직접 지급(check), 세부반 매핑 확인 필요(check).

## 8. 남은 제한

- 추천은 한 겹의 반 구분만 본다(`토탈공예미니어처1A` 같은 두 겹은 수동). 요일 접두('월요전래놀이')·오타는 추천 대상이 아니다.
- 연결은 학년도 단위다. 학기 중 구성이 바뀌면 변경 이력과 월 확정으로 추적한다.
- 세부반 단위의 환불·재원경정·자유수강권은 종전대로 세부반 프로그램에 등록한다(통합 행은 합산만).

# P7-1.2 보완 — 월 확정과 매핑 변경의 안전성 (2026-10-13)

## 9-1. 분석 결과 (수정 전)

| 질문 | 수정 전 | 문제 |
|---|---|---|
| 월 확정 지문에 무엇이 드나 | 원장 거래(전 상태)·배분·정정 상태 | 세부반 연결·그룹 구성은 없음 → 원장을 안 바꿔도 검증 결과가 달라지는 변경을 잡지 못함 |
| 매핑 변경 차단 기준 | 세부반 자신의 거래·배분이 있는 달이 확정이면 차단 | 통합 프로그램·그룹·추천 판정을 통한 간접 변화는 검사하지 않음 |
| 영향 월 산출 | 세부반의 거래 월 | 이름이 아닌 id 기준이긴 하나 "결과가 달라지는가"를 보지 않음 |
| '매핑 확인 필요' 판정 | 연도 전체의 추천 상태 | 세부반 거래가 없는 달의 통합 행까지 판정이 바뀜(다른 달 자료가 이 달 결과를 바꿈) |

## 9-2. 수정

1. **영향 월 = 실제 결과가 달라지는 달.** 미리보기는 변경 뒤의 연결 상태로 학년도의 거래가 있는 달마다 대조 엔진을 다시 돌려(`recon::row_digests`, 판정·금액·재원별·합산 세부반만 — 표시 방식·메모·시각 제외) 변경 전과 행 단위로 비교한다. 세부반·기존/새 통합 프로그램·그룹·배분·재원경정·환불·추천 판정이 모두 같은 엔진으로 계산되므로 어떤 경로의 간접 영향도 빠지지 않고, 결과가 안 바뀌는 관계 변경(통합 프로그램에만 거래가 있는 달)은 차단하지 않는다. 다른 학년도는 보지 않는다.
2. **차단 기준**: 영향 월 중 하나라도 확정이면 전부 차단. 메시지 형식: `'세부반' (기존 → 변경 후): 2026년 9월 회계가 확정되어 있어 프로그램 연결을 변경할 수 없습니다. 해당 월을 재개한 후 매핑을 변경하고 다시 확정해 주세요. (달라지는 검증 행 N개)`.
3. **'매핑 확인 필요' 판정을 달 단위로**: 그 달에 거래가 있는 세부반 후보에 대해서만 통합 행을 매핑 확인 필요로 본다.
4. **지문 형식 2**: 형식 1 내용 뒤에 그 달에 거래(모든 상태)·배분이 있는 프로그램의 연결(`l|프로그램|통합`)과 그 프로그램·그 달의 거래가 얽힌 그룹의 구성(`g|그룹|구성원…`)을 더한다. 스냅샷에 `"v": 2` 와 `links`·`groups` 를 남긴다. 다른 달·다른 학년도의 연결 변경은 이 달 지문에 영향이 없고, 시각을 쓰지 않아 같은 초의 변경도 잡힌다.
5. **구형 호환**: 스냅샷에 `v` 가 없는 확정(P6·v9~v10 초기)은 형식 1 로 해석해 **형식 1 로 다시 계산해 비교**한다(정상 확정을 변조로 오판하지 않음, 요약에 "구형 지문" 표시). 기존 확정 행은 다시 쓰지 않고, 재확정부터 형식 2 가 된다. 스키마 변경 없음(v10 유지, 마이그레이션 없음).
6. **미리보기 = 적용**: 적용은 같은 `preview` 를 다시 돌려 하나라도 막히면 아무것도 쓰지 않는다(트랜잭션). 미리보기 때 본 현재 연결(`expectedParentId`)이 적용 직전과 다르면 충돌로 막는다. 차단된 변경은 연결표·이력·감사에 남지 않는다.
7. `month_changes` 에 지문 형식·연결 변경·그룹 변경 표시.

## 9-3. 시험 (`program_link_close_tests.rs`, 8건 = 지시서 8장 A~F 34개 항목) · 실제 9월 자료

실제 자료(메모리 DB): 추천 40건 확정 후 9월 확정(지문 형식 2) → 로봇과학B 해제 시도는 "2026년 9월 회계가 확정되어 있어…" 로 차단 → 재개 → 해제 → 확정 뒤 변경 감지(연결 변경) · 원장 총액 불변 · 로봇과학 교재·재료비 기준액 1,080,000 → 540,000(로봇과학B 는 다시 추천 상태 → 매핑 확인 필요) → 재확정(새 지문) → 추가 변경 차단 → 확정 이력 3건 보존.

## 9-4. 남는 제한

- 지문 형식 1 로 확정된 달은 연결 변경을 지문으로 잡지 못한다(차단은 된다). 재확정하면 형식 2 가 된다.
- 영향 월 산출은 달마다 대조 엔진을 두 번 돌린다(12달 × 2). 실제 9월 규모(900여 거래)에서 수십 ms 수준.
