# P6 — 배포 전 보안 강화 · Windows 설치본 · 자동 업데이트 · 최종 검증

작성 2026-10-13. 앞선 문서: [06-P5-운영.md](06-P5-운영.md) 등. 앱 버전 **0.1.0**, 스키마 **v9**.

## 1. 자료가 있는 곳 (실제 설치본 기준)

| 자료 | 위치 |
|---|---|
| SQLite DB | `%APPDATA%\kr.school.asaccounting\asaccounting.db` (+ `-wal`, `-shm`) |
| 원본 엑셀 보관 | `%APPDATA%\kr.school.asaccounting\uploads\<sha256>.<ext>` |
| 백업 (기본) | `%APPDATA%\kr.school.asaccounting\backups\` — 설정에서 다른 드라이브·USB·네트워크 공유로 바꿀 수 있다 |
| 작업 이력 | `%APPDATA%\kr.school.asaccounting\ops-history.jsonl` |
| 설정 | DB 안 `app_setting` (백업 경로·암호화 방식·보관 개수·자동 백업) |
| 로그 | `%APPDATA%\kr.school.asaccounting\logs\` |
| 임시 파일 | 자료 폴더·백업 폴더 안 `.backup-*` · `.restore-*` · `.tmp-*` (시작 때 정리) |
| 프로그램 | `%LOCALAPPDATA%\Programs\방과후 회계 검증 매니저\` (현재 사용자 설치, 관리자 권한 불필요) |

환경변수 `ASACCOUNTING_DATA_DIR` 가 있으면 그 폴더를 자료 폴더로 쓴다(연습용·시험용). 프로그램을 제거해도 자료 폴더는 지우지 않는다.

## 2. 백업 암호화 (`ops::crypto`)

- 형식 `.asbk` = `ASBK1\n` + 헤더 JSON 한 줄 + AES-256-GCM 암호문(헤더를 추가 인증 데이터로 묶음). 헤더에는 방식·nonce·KDF 매개변수·salt·(DPAPI 로 감싼 키)만 있고 학생·학교 정보는 없다. 파일명에도 없다.
- **현재 Windows 계정용(DPAPI)**: 임의의 32바이트 키로 패키지를 암호화하고 키를 `CryptProtectData`(사용자 범위, 앱 고유 엔트로피)로 감싼다. 비밀번호 입력이 없어 자동 백업 기본값. 다른 PC·다른 계정에서는 풀 수 없다(그때는 안내 문구).
- **다른 PC 이전용(비밀번호)**: Argon2id(m=64 MiB, t=3, p=1, salt 16바이트)로 키를 유도한다. 비밀번호는 DB·설정·로그·오류 메시지·Git 어디에도 적지 않는다(시험 8). 잊으면 복원할 수 없음을 화면에 안내한다.
- 라이브러리: `aes-gcm` · `argon2` · `zeroize` · `windows-sys`(DPAPI). 키를 소스에 두지 않는다.
- 검증 순서: 형식 확인 → 복호화(인증 태그) → 패키지 구조·체크섬·전체 해시 → SQLite `integrity_check`·외래키 → 주요 표 → 메타데이터. 비밀번호 오류와 손상은 같은 메시지로 차단된다.
- 옛 `.zip`(P5) 백업은 그대로 읽히되 "이 백업 파일은 암호화되지 않았습니다" 로 표시한다. 자동 변환·삭제는 없다.
- 복호화된 임시 zip 은 자료 폴더(사용자 프로필, 본인만 접근) 안 임시 폴더에 두고 작업 뒤 지운다. 비정상 종료로 남은 것은 다음 시작 때 정리한다.

## 3. 사용자 지정 백업 경로

데이터 관리 → 백업 설정에서 경로를 고르거나 적고 '경로 검사'(존재·쓰기 가능·남은 공간)를 한다. 지정 경로는 자동으로 만들지 않는다 — 없으면 USB 분리·네트워크 끊김으로 본다. 백업은 `.tmp-…` 임시 파일로 만들어 검증까지 끝낸 뒤 최종 이름으로 바꾸며, 실패하면 임시 파일을 지우고 작업 이력에 '실패'로 남긴다. 자동 백업이 지정 경로를 못 쓰면 실패를 기록하고(설정이 켜져 있으면) 기본 경로에 대체 백업하되 목록에 실제 저장 위치와 '대체 저장'을 표시한다. 클라우드 업로드는 없다.

## 4. 월 확정 후 변경 감지 (스키마 v9)

확정 때 그 달의 확정 대상 자료 — 원장 거래 전부(id·상태·단계·금액·재원·프로그램·학생·항목·흐름·종류·처리일·이동 묶음), 배분(id·거래·프로그램·금액·상태), 정정(id·상태·처리일·금액) — 를 id 순 고정 형식으로 이어 SHA-256 지문을 `month_close.fingerprint` 에, 거래·정정·배분 id 목록을 `snapshot_json` 에 남긴다. 지금 지문이 다르면 '확정 후 변경' 이고 스냅샷과 비교해 새 거래·상태가 바뀐 거래·정정 변경·배분 변경을 가려낸다(`year::month_changes`). 시각 비교를 쓰지 않으므로 같은 초의 변경도 잡힌다. 지문이 없는 옛 확정 행은 그대로 두고 시각 비교로 해석한다. 재개 뒤 정정하고 재확정하면 새 지문이 기준이 된다. 확정 상태의 정정·업로드 차단은 기존 정책 그대로다.

## 5. Windows 설치본

NSIS(현재 사용자 설치, 한국어). `npm run app:build` → `src-tauri/target/release/bundle/nsis/방과후 회계 검증 매니저_0.1.0_x64-setup.exe` (+ `.sig`). 설치본에는 코드·아이콘·실행 파일만 들어가며 자료·백업·키·로그는 `.gitignore` 로 저장소에도 없다. 버전은 `package.json` · `src-tauri/Cargo.toml` · `src-tauri/tauri.conf.json` 세 곳에 같은 값.

## 6. 자동 업데이트

- `tauri-plugin-updater` + `tauri-plugin-process`. 공개키는 `tauri.conf.json` 의 `plugins.updater.pubkey`, 개인키는 저장소 밖 `%USERPROFILE%\.tauri\asaccounting.key`(.gitignore `*.key`). 서명이 맞지 않는 설치 파일은 플러그인이 거부한다. HTTPS 만 쓰고 비보안 전송 옵션은 켜지 않았다.
- 배포 주소(예정): `https://github.com/lohemal/afterschool-accounting/releases/latest/download/latest.json`. 저장소는 아직 없다 — **사용자 승인 뒤** 만든다.
- 화면: 설정 → 업데이트. 현재 버전·새 버전·변경 사항·진행률을 보여 주고, 담당자가 '백업 후 업데이트 설치'를 누르면 **업데이트 직전 백업**(보호 종류)을 만든 뒤 내려받아 설치한다. Windows 에서는 설치 프로그램이 앱을 끝내고 다시 켜므로 `relaunch()` 를 부르지 않는다(형제 프로젝트에서 겪은 경쟁 버그).
- 새 버전이 스키마를 올리면 기존 마이그레이션 직전 백업 구조가 그대로 돈다. 업데이트 실패(다운로드·서명·설치)는 화면에 사유를 보여 주고 기존 버전·자료를 그대로 둔다.
- Release 는 `.github/workflows/release.yml`(태그 `v*`)이 만든다: 서명 빌드 → 영문 이름(`asaccounting_<버전>_x64-setup.exe`)으로 복사 → `latest.json`(BOM 없음)·`SHA256SUMS.txt` 생성. 한글 앱 이름은 GitHub 첨부 파일명에서 깨지므로 영문 이름을 쓴다.

## 7. 검증 (P6-4)

실제 다른 PC 는 없어 **별도 자료 폴더(`ASACCOUNTING_DATA_DIR`)** 로 검증했다. 결과는 완료 보고에 적는다. 외부 Release 가 없어 실제 업데이트 채널로 받는 시험은 하지 못했고, 서명 검증은 생성된 `.sig` 를 공개키로 직접 검증하는 시험(`p6_e_installer_signature_verifies`)으로 대신했다.

## 8. 남은 제한 · 배포 전 사용자 작업

- GitHub 저장소(비공개 권장) 생성 → Secrets `TAURI_SIGNING_PRIVATE_KEY` 에 개인키 내용 등록 → `master` push → 태그 `v0.1.0` push → Release 자산 4개 확인 → 이전 버전 설치본에서 앱 내 업데이트 실측.
- 개인키 파일은 저장소 밖에 보관·백업한다. 잃으면 업데이트 서명을 다시 만들 수 없다(새 공개키로 재설치 필요).
- 첫 배포 뒤 실제 운영 DB(v5)는 첫 실행 때 마이그레이션 직전 백업을 만들고 v9 로 올라간다.
